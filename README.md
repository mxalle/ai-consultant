# ai-consultant

AI-консультант в Telegram для локального бизнеса — барбершопа, тату-студии,
детейлинга. Клиент пишет боту, бот отвечает от имени администратора: про услуги,
цены, мастеров, адрес и часы работы. Отвечает **только** по базе знаний бизнеса,
под каждым ответом — кнопка «Записаться» на онлайн-запись (YCLIENTS, DIKIDI).

Если ответа в базе знаний нет или нужен человек (жалоба, скидка, перенос записи),
бот ничего не выдумывает: пишет клиенту «Уточню у администратора и вернусь
с ответом» и пересылает вопрос владельцу. Владелец отвечает reply на это
сообщение — бот отправляет ответ клиенту.

Это MVP для демо: один бизнес на один запуск бота.

## Как это работает

```
клиент ──текст──▶ бот ──▶ rate limit? ──▶ история (10 последних) + база знаний ──▶ LLM
                                                                                     │
          ◀── ответ + кнопка «Записаться» ◀──────────── обычный ответ ◀─────────────┤
          ◀── «Уточню у администратора…» ◀── вопрос владельцу ◀── [ESCALATE] ◀──────┘
                                                   │
владелец ── reply на вопрос ──▶ бот ──▶ «Ответ администратора: …» ──▶ клиент
```

- База знаний — обычный текстовый файл `knowledge/<slug>.md`. Он маленький,
  поэтому читается при старте и целиком кладётся в system prompt (без RAG).
- LLM — любой OpenAI-совместимый API (OpenRouter, YandexGPT, …): провайдер
  меняется в `.env`, код не трогаем.
- Модель помечает вопросы для человека маркером `[ESCALATE]` в начале ответа;
  бот вырезает его и пересылает вопрос владельцу.
- История, эскалации и статистика — в Postgres.

## Стек

- aiogram 3 (long polling), SQLAlchemy 2.0 async + asyncpg, Alembic, pydantic-settings
- `openai` (`AsyncOpenAI`) как клиент к OpenAI-совместимому API
- PostgreSQL 16 через `docker-compose.yml`
- pytest + pytest-asyncio; тесты на SQLite в памяти, LLM замокан — без Docker и сети

## Запуск локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env              # заполнить, см. ниже
docker compose up -d              # postgres на localhost:5433
.venv/bin/alembic upgrade head    # создать таблицы
.venv/bin/python -m bot.main      # запустить бота
```

Обязательные значения в `.env`:

| Переменная | Откуда взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| `OWNER_CHAT_ID` | id владельца — у @userinfobot. Можно id группы, куда добавлен бот |
| `BUSINESS_NAME` | название бизнеса, например `Барбершоп «Кузня»` |
| `BOOKING_URL` | ссылка на онлайн-запись бизнеса (https) |
| `KNOWLEDGE_FILE` | путь к базе знаний, по умолчанию `knowledge/demo_barbershop.md` |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | у провайдера LLM; примеры — в `.env.example` |

Необязательные: `RATE_LIMIT_PER_HOUR` (30), `LLM_TIMEOUT` (30 с),
`LLM_DISABLE_REASONING` (`false`; `true` для thinking-моделей на OpenRouter),
`BOT_TIMEZONE` (`Europe/Moscow`, для «сегодня» в `/stats`), `DEBUG`.

Если чего-то не хватает, бот не стартует и перечисляет, каких переменных нет.

### Как показать демо

1. Владелец (аккаунт или группа из `OWNER_CHAT_ID`) один раз пишет боту `/start` —
   иначе Telegram не даст боту написать ему первым, и эскалации не дойдут.
2. С **другого** аккаунта пишем боту как клиент: «сколько стоит стрижка с
   бородой?», «а где вы находитесь?», «как добраться от метро?».
3. Вопрос не из базы знаний — «можно скидку 20%?», «хочу перенести запись» —
   уходит владельцу. Владелец отвечает reply, клиент получает ответ.
4. Владелец отправляет `/stats` — сколько клиентов и сообщений за сегодня и за
   неделю, сколько вопросов ждут ответа.

Сообщения из `OWNER_CHAT_ID` никогда не идут в LLM, поэтому проверять бота как
клиент с аккаунта владельца не получится — нужен второй аккаунт (или группа
в роли чата владельца).

## Команды

| Кто | Команда | Что делает |
|---|---|---|
| клиент | `/start` | приветствие от имени бизнеса + кнопка «Записаться» |
| клиент | `/reset` | бот забывает прошлую переписку |
| владелец | `/stats` | клиенты и сообщения за сегодня и 7 дней, открытые эскалации |
| владелец | reply на вопрос | ответ уходит клиенту |

## Защита

- Не больше `RATE_LIMIT_PER_HOUR` сообщений в час от клиента (считается по
  таблице `messages`). Сверх — вежливый отказ без запроса к LLM.
- Сообщения длиннее 1000 символов обрезаются.
- Фото, голосовые, стикеры — «Пока понимаю только текст».
- Ответ модели уходит обычным текстом, без `parse_mode`: markdown или HTML от
  модели не ломают отправку.
- Ошибка или таймаут LLM — клиент получает «Сейчас не могу ответить, напишите,
  пожалуйста, чуть позже или запишитесь по кнопке», ошибка пишется в лог.
- Промпт велит отвечать только по базе знаний и игнорировать просьбы сменить
  роль или показать инструкции.

## Новый клиент (бизнес)

Один бизнес = один бот = один `.env` = своя база данных.

1. В @BotFather создать нового бота (`/newbot`), взять токен. Там же можно
   задать аватар и описание (`/setuserpic`, `/setdescription`).
2. Написать базу знаний `knowledge/<slug>.md` по образцу
   `knowledge/demo_barbershop.md`: услуги с ценами и длительностью, мастера,
   адрес, как добраться, часы, частые вопросы. Чем точнее файл, тем реже бот
   зовёт владельца.
   Пишите ответы целиком, без отсылок «см. таблицу выше» — модель повторяет
   их клиенту дословно.
3. Сделать отдельную копию проекта (например, `git clone` в папку
   `ai-consultant-<slug>`) и в ней свой `.env`: новый `TELEGRAM_BOT_TOKEN`,
   `OWNER_CHAT_ID` владельца, `BUSINESS_NAME`, `BOOKING_URL`,
   `KNOWLEDGE_FILE=knowledge/<slug>.md`.
4. Своя база в том же Postgres:
   ```bash
   docker compose exec postgres createdb -U consultant <slug>
   # в .env: DATABASE_URL=postgresql+asyncpg://consultant:consultant@localhost:5433/<slug>
   .venv/bin/alembic upgrade head
   ```
5. Владелец пишет новому боту `/start`, затем запускаем `.venv/bin/python -m bot.main`.

После правки базы знаний бота нужно перезапустить: файл читается при старте.

## Тесты

```bash
.venv/bin/pytest
```

Docker и ключи не нужны: SQLite в памяти, вызовы LLM и Telegram замоканы.

## Структура

```
app/config.py              настройки из .env (pydantic-settings)
app/database.py            async engine, session_factory, Base
app/models.py              Conversation, ChatMessage, Escalation
app/services/              все запросы к БД
  conversations.py           история клиента, /reset
  escalations.py             вопросы владельцу и ответы на них
  rate_limit.py              сообщений за последний час
  stats.py                   цифры для /stats
bot/main.py                точка входа, проверка .env, сборка промпта, long polling
bot/middlewares.py         одна сессия БД на апдейт
bot/prompt.py              system prompt, разбор [ESCALATE], обрезка текста
bot/llm.py                 клиент OpenAI-совместимого API
bot/keyboards.py           кнопка «Записаться»
bot/handlers/owner.py      чат владельца: reply на эскалацию, /stats
bot/handlers/client.py     клиент: /start, /reset, вопросы, нетекстовые сообщения
knowledge/                 базы знаний бизнесов
alembic/                   миграции
tests/                     pytest
```
